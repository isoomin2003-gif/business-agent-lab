# AimTrace30

PC 마우스로 플레이하는 에임 훈련 앱입니다. 사격장 바닥에 한 번에 하나씩 서는 사람형 봇 표적의 **머리**를 클릭하는 네 가지 사격 모드(기본·움직임·분석·온라인 랭크)와, 움직이는 공을 조준점으로 따라가는 **트래킹 모드**가 있습니다. 이 앱을 만든 이유는 제가 하고 원하던 에임 훈련 앱을 만들고 싶었기 때문입니다. 또한 저처럼 에임 연습을 하고 싶은 사람들이나 FPS초보들을 위해 만들었습니다. 
처음에는 단순한 에임 훈련 앱이었으나 AI와 얘기를 하며 실현 가능한 것들을 더 추가하고 구체적으로 만들게 되었습니다. 

## 1. 실행 방법

요구 사항: **Node.js 22.13 이상** (`node:sqlite` 사용. Node 24 권장)

```bash
npm start
```

브라우저에서 `http://localhost:3000` 에 접속합니다. 포트는 `PORT`, DB 파일 위치는 `DB_PATH`(기본값 `data/ranking.db`) 환경 변수로 바꿀 수 있습니다.

```bash
PORT=8080 DB_PATH=/var/data/ranking.db npm start
```

테스트 실행:

```bash
npm test
```

### Windows에서 실행하기 (Ubuntu/WSL)

1. 받은 `AimTrace30.zip`을 오른쪽 클릭 → ‘압축 풀기’ 합니다.
2. 풀린 `AimTrace30` 폴더 안에서 Shift + 오른쪽 클릭 → ‘터미널에서 열기’, 그다음 `wsl`을 입력해 Ubuntu로 들어갑니다.
3. Ubuntu 홈 폴더로 복사한 뒤 실행합니다. (`/mnt/c` 아래에서 실행하면 SQLite 파일 잠금 문제가 생길 수 있음)

```bash
cd ~/AimTrace30 && npm start
```

4. Windows 브라우저에서 `http://localhost:3000` 에 접속합니다. 이전 화면이 보이면 `Ctrl + F5`로 새로고침합니다. 소리는 첫 클릭 후 재생됩니다.

Ubuntu의 Node가 22.13보다 낮으면 `nvm install 24`로 새 버전을 설치하세요.

## 2. 공통 규칙

- 표적은 항상 **한 번에 하나만** 등장합니다.
- 판정 영역은 머리·몸통·발의 세 부분입니다.
- 머리 명중: 판정상 즉시 제거됩니다. 몸통과 발은 기록용입니다.
- 시간 초과: 노출 시간이 끝나는 순간 판정상 즉시 사라집니다.
- ‘처리된 표적’ = 머리를 맞혀 제거한 표적 + 시간 초과로 사라진 표적. 몸통·발 명중은 처리로 세지 않습니다.
- 플레이 중 `Esc` 또는 ‘중도 종료’ 버튼으로 그만둘 수 있습니다. 중도 종료 결과는 정상 완료와 구분해 표시합니다.
- 결과 화면에서 ‘다시 하기’ 또는 ‘모드 선택으로’를 고를 수 있습니다. 

## 3. 모드별 규칙과 종료 조건
- 기본 모드: 정지 표적을 맞히며, 난이도가 높을수록 노출 시간이 짧아집니다. 성공·실패와 관계없이 표적 30개 처리 후 종료합니다.
- 움직임 모드: 좌우로 움직이는 표적을 맞힙니다. 기본 모드보다 노출 시간이 길며, 표적 30개 처리 후 종료합니다.
- 분석 모드: 정지형·이동형 중 선택하고 보통 난이도 조건으로 표적 30개를 진행한 뒤 조준 경향을 확인합니다.
- 랭크 모드:머리 명중 시 +1점, 시간 초과 시 -1점이며, 20점에 도달하기까지 걸린 시간을 기록합니다. 음수로 내려갈 수 있습니다. 

종료 화면 :
- 기본·움직임: 성공한 표적 수 / 전체 표적 수, 표적별 결과, 진행 시간, 시간 초과로 놓친 표적 수, 발사 기준 헤드 적중률(= 머리 명중 ÷ 전체 발사 × 100, 발사 0회면 ‘측정 불가’).
- 랭크: 20점 달성 시간과 서버에서 확인한 실제 순위, 성공한 표적 수, 놓친 표적 수, 랭킹 등록 결과.

## 4. 분석 지표 계산 방식

발사 횟수와 표적 수를 구분해 기록합니다. 
**클릭 분포도**: 모든 클릭을 클릭 당시의 머리 중심을 원점으로 정렬해 실루엣 위에 겹쳐 그립니다. 
**규칙 기반 피드백**: 판단 조건과 최소 데이터 기준은 [`public/js/analysis.js`](public/js/analysis.js)의 `ANALYSIS_RULES`에서 관리합니다. 외부 AI API는 사용하지 않습니다.

- 첫 클릭 위치 경향: 발사가 있었던 표적의 첫 클릭만 사용하며, 사용한 개수와 제외한 개수를 표시합니다.
- 지나침(오버슈트): 표적 등장 당시 커서 위치와 이후 이동 경로를 기록합니다. 
- 결과는 “한 번의 30개 테스트에서 나온 이번 플레이의 경향”으로 표시하며, 다른 FPS 게임의 적정 감도를 확정하지 않습니다.

## 5. 트래킹 모드

- 사람 표적 대신 공 하나가 30초 동안 계속 움직입니다. 맞히면 사라지는 방식이 아닙니다.클릭할 필요가 없습니다.마우스를 움직이기만 하면 됩니다.
- 조준점 중심이 공 안에 있는 동안 추적 성공 시간이 누적됩니다. 성공 중에는 공 안쪽 테두리가 초록색 굵은 선으로 바뀝니다.

결과 지표:
추적 성공률: 얼마나 공 안에 조준점이 들어갔나 알 수 있습니다.
최장 연속 추적 시간: 조준점이 공 밖으로 나가지 않고 이어진 가장 긴 시간

## 6. 화면 구성 (홈·결과)

홈 화면: 게임 로비 형태입니다. 왼쪽 큰 메뉴에서 기본·움직임·분석·랭크·트래킹 중 하나를 고르면 옆 패널에 그 모드의 설명과 설정만 나타납니다.오른쪽 위 ‘설정’에서 소리를 조절합니다.
결과 화면: 결과 화면에서 헤드 적중률, 맞힌 개수 등을 볼 수 있습니다. 
- 정상 완료와 중도 종료(트래킹은 ‘훈련 중단’)를 구분합니다. 중도 종료 시 기본·움직임은 ‘성공 / 처리한 표적’으로 표시하고 미진행 표적은 실패로 계산하지 않습니다. 분석 모드는 30개를 채우지 않으면 분석 결과를 만들지 않습니다.

## 7. 오디오

모든 소리는 **Web Audio API로 브라우저에서 직접 합성**합니다(`public/js/audio.js`). 외부 음원 파일을 쓰지 않으므로 별도 라이선스가 없고(이 프로젝트의 자체 제작물), 음원 로딩 실패도 없습니다. 참고 게임의 음악·효과음은 사용하지 않았습니다.

**사격 소리 = 발사음(총성) + 명중음**
- **총성**: 어디를 맞히든 총성은 완전히 같습니다. 명중했다고 총성을 다른 소리로 바꾸지 않습니다.
- 명중음은 총성과 같은 순간에 시작해 위에 겹칩니다.

- 플레이 중 표적이 사라진 뒤 다음 표적이 나오기 전 대기 시간에 클릭해도 총성만 재생합니다(허공 발사와 같은 소리, 탄흔 표시). 이 클릭은 발사 기록·적중률·랭크 서버 검증에는 포함하지 않습니다. 기본·움직임·분석·랭크 모두 같은 규칙입니다.

**트래킹 피드백 소리**
- 공 안에 조준점이 있을 경우에는 소리가 납니다. 공 밖에 있을 때는 배경 음악만 들립니다.

## 8. 게임 배경

배경은 화면 표시 전용입니다. 
- 기본·움직임·트래킹 모드는 홈에서 새 게임을 시작할 때 준비된 배경 중 하나를 무작위로 고릅니다.
**첨부 이미지 사용 여부**: 첨부된 배경 이미지 두 장 원본은 넣지 않고 분위기와 공간 구성만 참고해 새로 그렸습니다. 발로란트 홈 화면과 Aimlabs 결과 화면 이미지는 화면 배치 참고용으로만 썼으며, 로고·캐릭터·UI는 복제하지 않았습니다.

## 9. 검증 내용 (+직접 플레이한 검증 사례)

- 표적이 항상 하나만 존재하고, 정확히 0.5초 간격으로 다음 표적 등장, 표적이 영역 밖으로 나가지 않고 항상 바닥 위에 섬
- 부위 판정: 머리는 표적 안, 목 틈·팔과 허리 사이·다리 사이는 표적 밖 - 머리를 조준하면 제거되고 몸통·발 명중 후 유지되고, 시간이 초과되면 사라지는 것을 확인했습니다.
- 노출 시간: 기본 1.5/1/0.5초, 움직임은 기본보다 김, 분석 정지형 1초, 랭크 1초 (규칙 버전 rank-v5) - 직접 실행을 통해 움직임 모드에서 노출 시간을 0.5초에서 1초로 늘렸습니다. 
- 몸통·발 명중 후 표적 유지, 노출 시간 초기화 없음, 이후 머리 재조준 가능
- 움직이는 표적: 생성 위치가 아닌 클릭 순간 위치로 판정, 짧은 간격의 지그재그 방향 전환(초당 1회 이상), 속도 제한, 순간 반전 없는 부드러운 전환, 영역 밖으로 나가지 않음, 같은 시드는 같은 경로
- 기본·움직임·분석 모드: 모두 놓쳐도, 일부 성공해도 정확히 30개 처리 후 종료 (31번째 표적 없음), 20점에서 조기 종료하지 않음 - 실행해본 결과 30개의 표적이 다 나오면 종료됩니다.
- 랭크: 30개를 넘어도 20점 미만이면 계속, 음수 점수, 표적당 한 번의 시간 초과 감점, 20점 도달 즉시 종료 - 실행해본 결과 표적을 못 맞추면 -1이 되는 것을 확인했고 0에서 음수로 되는 것도 확인했습니다. 
- 발사 0회·성공 0개에서 ‘측정 불가’ 처리 (NaN 없음), 첫발 헤드 계산에서 미발사 표적 제외 - 실제로 한 번도 발사하지 않고 표적이 모두 지나가게 했을 때 오류 없이 결과 화면이 표시되는 것을 확인했습니다. 
- 분석 피드백이 데이터 기준을 충족할 때만 생성되고, 경로 없이 지나침을 판단하지 않음 - 실제로 확인해본 결과 중간에 나가게 되면 결과를 볼 수 없었습니다.

## 10. 구현상의 한계
- 분석 결과는 한 판(30개)의 경향이며 통계적으로 확정된 결론이 아닙니다. 사용자의 평소 실력을 확정하기 어렵다. 실제 FPS 게임의 실력 향상 효과도 검증하지 못했다.
- 내 컴퓨터에서는 플레이를 확인했지만, 다른 컴퓨터에서의 실행과 공개 서버를 통한 사용자 간 기록 저장, 순위 공유는 아직 검증하지 못했다. 
- 난이도에 대해서 다양한 실력의 사용자에게 적절한지는 추가 확인이 필요하다. 

## 11. 효과적이었던 작업 방법
- 게임 규칙을 구체적으로 적기: 내가 생각했던 아이디어들을 정확하게 구체적으로 말하는 것이 중요한 것 같습니다. 두더지 게임처럼 표적이 하나씩 등장한다고 설명하고, 머리 명중과 시간 초과의 처리 방식을 구분했습니다. Claude Code가 원하는 게임 구조를 이해하는 데 도움이 됐습니다.
- 사진이나 영상을 제공하기: 글로 설명하기 어려운 디자인과 동작을 구체화하는 데 도움이 됐습니다. 
- 직접 플레이하며 수정하기: 구현된 게임을 반복해서 플레이하며 표적 이동 속도와 소리 등을 확인했습니다. 실제 사용 중 느낀 불편을 바탕으로 수정 요청을 구체화할 수 있었습니다.

## 12. 어려움과 대응 3가지
- 디자인 의도 전달: 글만으로 원하는 화면을 전달하기 어려웠다. 참고 이미지를 첨부해 수정했지만 제 의도대로 완벽히 수정되지는 않았습니다. 그래도 만족할 만한 화면으로 개선했습니다. 
- 난이도 조절: 움직임 모드의 표적이 너무 빨라 플레이 하기 어려워 속도를 조절했습니다. 다양한 사용자에게 적절한지 검증을 하지 못했습니다. 
- 배포 방법 이해: 다른 사람도 게임을 실행하고 랭크 기록을 공유하게 하고 싶어 claude code에 물어봤습니다. 이해를 하기 좀 어려웠습니다. 또한 실제 친구의 컴퓨터에서 실행하거나 순위를 공유하는 단계까지는 검증하지 못했습니다.
